Finetuning Omnilingual ASR for Albanian

Nardi Xhepi Data Scientist
February 2026 10 min read

Low-resource languages like Albanian present unique challenges for automatic speech recognition systems. In this project, I finetuned the Omnilingual ASR 300M model on Albanian audio, achieving a 15.7% relative improvement in Word Error Rate using approximately two hours of training data and about six minutes of compute on an A100 GPU.

The Challenge

Albanian is considered a low-resource language in the context of speech recognition. While multilingual models provide decent baseline performance, they often struggle with language-specific phonetic patterns, dialectal variations, and common contractions that native speakers use in everyday speech.

About Omnilingual ASR

Omnilingual ASR is an open-source speech recognition system developed by Meta's FAIR research division. It supports over 1,600 languages, including more than 500 languages that previously had no ASR coverage at all. The model is built on the fairseq2 framework and released under the Apache 2.0 license.

The architecture uses an encoder-decoder design where the encoder performs self-supervised pre-training on speech representations, and an LLM-inspired decoder handles the sequence generation. The model comes in two sizes: a 7-billion parameter version for maximum accuracy, and a 300-million parameter version designed for efficiency and deployment on resource-constrained environments.

My goal was to leverage the 7B model's knowledge to improve the 300M model's performance on Albanian through pseudo-labeling, a form of knowledge distillation.

Building the Data Pipeline

The project required building a complete data pipeline from scratch:

  1. Audio Collection - Downloading Albanian content from YouTube using yt-dlp, converting to 16kHz mono WAV format
  2. Voice Activity Detection - Using Silero VAD to extract clean speech segments and remove music, silence, and noise
  3. Chunking - Segmenting audio into 30-second clips suitable for training
  4. Pseudo-labeling - Transcribing the training set using the 7B model to generate high-quality pseudo-labels via knowledge distillation
  5. Human Annotation - Manually annotating a small test set for reliable evaluation

I built a simple annotation dashboard using Flask and JavaScript that allows playback control, waveform visualization, and quick text editing. This made it practical to annotate the 31 test files needed for evaluation.

The Finetuning Approach

The official fairseq2 training recipe expects data in Apache Parquet format, which requires significant preprocessing overhead. Instead, I implemented a custom PyTorch training loop that works directly with the model's Seq2SeqBatch format, eliminating the need for complex data format conversions.

Key training decisions:

  • Selective freezing - Kept encoder weights frozen except for layer normalization, training primarily the decoder and attention layers
  • Gradient accumulation - Used accumulation over 4 steps with batch size 2, effectively training with batch size 8
  • Conservative learning rate - Set to 1e-5 with AdamW optimizer to preserve pretrained knowledge while adapting to Albanian
# Freeze encoder, train decoder
for name, param in model.named_parameters():
    if "encoder" in name.lower() and "layer_norm" not in name.lower():
        param.requires_grad = False
    else:
        param.requires_grad = True

The training loop uses gradient accumulation to simulate larger batch sizes on limited GPU memory: 

# Training hyperparameters
LEARNING_RATE = 1e-5
NUM_EPOCHS = 3
BATCH_SIZE = 2
GRAD_ACCUMULATION = 4  # Effective batch size: 8

optimizer = AdamW(
    [p for p in model.parameters() if p.requires_grad],
    lr=LEARNING_RATE,
    weight_decay=0.01
)

for epoch in range(NUM_EPOCHS):
    for batch_start in range(0, len(indices), BATCH_SIZE):
        batch = create_batch(batch_indices)
        
        # Forward pass
        output = model.forward(batch, return_logits=True)
        loss = output[0] / GRAD_ACCUMULATION
        loss.backward()
        
        if (num_batches + 1) % GRAD_ACCUMULATION == 0:
            torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)
            optimizer.step()
            optimizer.zero_grad()

The batch creation function constructs Seq2SeqBatch objects directly, bypassing the official Parquet-based data pipeline: 

def create_batch(indices):
    audio_examples = []
    for idx in indices:
        waveform, sr = torchaudio.load(train_paths[idx])
        if sr != 16000:
            waveform = torchaudio.transforms.Resample(sr, 16000)(waveform)
        if waveform.shape[0] > 1:  # Convert to mono
            waveform = waveform.mean(dim=0)
        if waveform.shape[0] > 480000:  # Truncate to 30s
            waveform = waveform[:480000]
        
        tokens = token_encoder(train_texts[idx])
        audio_examples.append({"audio_feature": waveform, "text": tokens})
    
    collated = full_collater(audio_examples)
    return Seq2SeqBatch(
        source_seqs=collated["audio_feature"]["seqs"].to(device, dtype),
        source_seq_lens=collated["audio_feature"]["seq_lens"],
        target_seqs=collated["text"]["seqs"].to(device),
        target_seq_lens=collated["text"]["seq_lens"],
        example={"lang": [LANGUAGE] * len(indices)}
    )

Results

After three epochs of training (approximately six minutes on an A100 GPU), the finetuned model showed significant improvement:

Metric Value
Baseline WER 54.91%
Finetuned WER 46.30%
Absolute Improvement 8.61 percentage points
Relative Improvement 15.7%

Where It Improved Most

Qualitative analysis of the transcription differences revealed several patterns where the finetuned model consistently outperformed the baseline:

  • Albanian contractions - Common shortened forms like "s'ka" (there isn't), "t'i" (to you), "m'ke" (you have me) that the baseline model often expanded incorrectly
  • Dialectal vocabulary - Regional expressions and colloquialisms that appear frequently in conversational speech but are underrepresented in multilingual training data
  • Albanian place names - Geographic locations and proper nouns specific to Albanian-speaking regions
  • Code-switching patterns - Natural mixing with common loanwords that Albanian speakers use from English, Italian, and Turkish

Technical Challenges

Several obstacles required creative solutions:

  • Dependency conflicts - The omnilingual-asr package has specific PyTorch and fairseq2 version requirements that conflict with Colab's default environment. Careful version pinning (torch==2.4.0, torchaudio==2.4.0) was essential.
  • Batch format - Bypassing the official Parquet-based training pipeline required understanding the internal Seq2SeqBatch structure and manually constructing valid training batches.
  • Language code - The Omnilingual model uses ISO 639-3 language codes with script suffixes. Albanian required als_Latn (Tosk Albanian in Latin script) rather than the simpler "sq" code.

Lessons Learned

This project reinforced several principles for working with low-resource language ASR:

  1. Pseudo-labeling works - Using a larger teacher model to generate training labels is remarkably effective, even with a relatively small dataset
  2. Quality over quantity - Clean, well-segmented audio with accurate pseudo-labels outperforms larger amounts of noisy data
  3. Test set integrity matters - Human-annotated test data, clearly separated from training, is essential for trustworthy evaluation
  4. Adapters over full finetuning - Freezing most encoder weights preserved the model's general speech recognition capabilities while allowing specialization for Albanian

"Two hours of training data and six minutes of compute delivered meaningful improvements for a low-resource language. The barrier to customizing ASR models for underserved languages is lower than many assume."

Future Directions

Several extensions could further improve performance:

  • Expanding the training dataset with more diverse speakers and recording conditions
  • Adding a language model for post-processing and improved coherence
  • Exploring LoRA or other parameter-efficient finetuning methods
  • Testing on the Gheg Albanian dialect to assess generalization

The complete implementation is available as a Colab notebook, demonstrating that meaningful ASR improvements for low-resource languages are achievable with modest computational resources and careful methodology.
